# Task 6：合规与风控方案

## 1. 实名认证流程

### 1.1 接入方式

平台提供三种实名认证接入方式，按优先级推荐如下：

| 接入方式 | 推荐优先级 | 实现说明 | 适用场景 |
|:---|:---:|:---|:---|
| 微信实名授权 | 首选 | 用户授权后获取微信实名信息（姓名、身份证掩码），与公安部接口或官方授权链路核验一致性 | 微信登录/小程序/App 场景 |
| 支付宝实名授权 | 次选 | 通过支付宝会员信息授权获取用户实名，校验姓名与身份证号匹配 | 支付宝登录或提现场景 |
| 第三方身份证 OCR + 二要素核验 | 兜底 | 用户上传身份证正反面，OCR 提取姓名、身份证号，再调用公安/运营商二要素接口核验 | 未授权微信/支付宝实名，或强合规要求 |

**推荐组合策略：**

- 默认优先使用微信/支付宝一键实名授权，降低用户操作成本，提升通过率。
- 当用户拒绝授权或授权信息不完整时，引导使用 OCR + 二要素核验完成实名。
- 所有实名信息必须与提现支付账户实名保持一致；不一致时拒绝提现或要求更换账户。

### 1.2 认证时机

```text
用户发起提现
    │
    ▼
判断账号是否已完成实名认证
    │
    ├── 否 ──▶ 拦截提现，跳转实名认证页面
    │              │
    │              ▼
    │         选择认证方式（微信/支付宝/OCR+二要素）
    │              │
    │              ▼
    │         完成认证，信息写入用户实名档案
    │              │
    │              ▼
    │         返回提现流程继续校验
    │
    └── 是 ──▶ 进入实名一致性/风控校验
```

**规则要点：**

- 首次提现前必须完成实名认证，未认证用户无法提交任何提现申请。
- 实名信息一经绑定，与账号永久关联，用户不能自行修改姓名、身份证号。
- 如需更正（如身份证变更），必须提交人工审核并上传公安机关出具的变更证明。
- 同一身份证最多绑定 3 个平台账号，超出时拒绝新账号实名并提示。

### 1.3 未成年保护策略

实名认证完成后，服务端根据身份证号解析出生日期，判定用户年龄并执行分级策略：

| 年龄段 | 判定标准 | 提现策略 | 游戏时长策略 | 充值/广告策略 |
|:---|:---|:---|:---|:---|
| 未成年人（< 18 岁） | 身份证出生日期距当前日期不足 18 年 | 禁止提现；已兑换现金余额保留但不可提现，账号成年后自动解除限制 | 接入国家新闻出版署防沉迷系统，周五/六/日及法定节假日 20:00-21:00 可玩，其他时段禁止登录 | 禁止充值；限制或关闭部分激励广告收益场景 |
| 成年人（≥ 18 岁） | 身份证出生日期距当前日期已满 18 年 | 正常提现，受通用风控规则约束 | 不受未成年人时长限制 | 按平台常规规则执行 |

**合规处理要点：**

- 实名信息需在服务端完成年龄判定，禁止客户端自行计算或绕过。
- 未成年人账号需在个人中心、提现页面显著位置提示限制原因。
- 对疑似成年人冒用未成年人身份的情况，触发人脸核验或人工复核。
- 定期与官方防沉迷实名库交叉校验，发现不一致时以官方库结果为准。

## 2. 反作弊规则

### 2.1 客户端反作弊

| 反作弊手段 | 具体措施 | 触发阈值/策略 |
|:---|:---|:---|
| 代码混淆 | 对游戏逻辑、网络请求、签名校验代码进行混淆，提高逆向成本 | 构建时默认开启，使用 ProGuard / IL2CPP / 自定义混淆方案 |
| 内存加密 | 对金币、得分、角色坐标等关键内存变量进行加密存储，定期校验完整性 | 运行时持续校验；发现内存被修改则强制退出或上报异常 |
| 签名校验 | 校验客户端安装包签名、资源文件哈希，防止二次打包 | 启动时校验；失败则禁止进入游戏 |
| 模拟点击检测 | 检测点击坐标规律性、操作间隔一致性、无传感器变化等脚本特征 | 单局内连续 30 秒操作方差低于阈值，或轨迹与真实人类分布差异过大时标记 |
| 调试/Hook 检测 | 检测 Xposed、Frida、Magisk、调试器挂载、模拟器环境 | 发现风险环境后限制结算奖励或强制退出 |

### 2.2 服务端校验

| 校验维度 | 校验规则 | 异常处理 |
|:---|:---|:---|
| 单局用时合理性 | duration_ms 必须大于该关卡理论最短时间，且不超过最大时长 | 超出阈值仅发放已收集金币或拒绝结算 |
| 收集数量合理性 | 普通金币、大宝箱、隐藏星星数量不得超过关卡配置上限 | 超出部分不计入奖励，并标记账号 |
| 通关路径合理性 | 校验关键坐标/状态轨迹是否物理可达，必要时抽样复核 | 无法复现则冻结本局奖励并进入人工复核 |
| 金币增长速率监控 | 单账号单日金币增长超过历史均值 3 倍或绝对阈值时触发监控 | 触发风控队列，暂停提现并复核 |
| 单局奖励上限校验 | 本局获得金币不得超过关卡理论最大值 | 超出部分拒绝发放，账号进入观察名单 |
| 时间戳与幂等校验 | 结算时间须在会话创建后，与服务端时间差 ≤ 5 分钟；同一 session_id 仅结算一次 | 拒绝异常请求并记录日志 |
| 签名校验 | 服务端对关键字段重新验签 | 验签失败直接拒绝结算 |
| 异常设备/账号标记 | 同一设备/IP 下大量账号、频繁新建账号、批量相似行为 | 标记为黑灰产账号，限制提现或封禁 |

### 2.3 处置措施

| 风险等级 | 判定条件 | 处置措施 |
|:---:|:---|:---|
| 低 | 首次轻微异常，如单局用时略低于合理区间但可解释 | 系统警告，记录行为日志，不处罚 |
| 中 | 多次异常结算、金币增速异常、疑似脚本但未造成大额损失 | 冻结可疑金币 7 天，期间禁止提现，复核后扣减或解冻 |
| 高 | 确认使用修改器、脚本挂机、批量养号、虚假设备 | 清零违规收益，封禁提现功能 30~180 天 |
| 极高 | 黑灰产攻击、欺诈提现、洗钱嫌疑 | 永久封号，冻结全部余额，保留证据并视情况报案 |

## 3. 提现风控策略

### 3.1 多维度限频规则

| 维度 | 限频规则 | 说明 |
|:---|:---|:---|
| 身份证 | 同一身份证每日最多提现 1 次，每月累计不超过 500 元 | 防止同一身份通过多账号套利 |
| 设备 | 同一设备每日最多提现 2 次，每月累计不超过 800 元 | 识别共享设备、模拟器、云手机 |
| IP | 同一公网 IP 每日最多提现 5 次 | 防止机房、代理、VPN 批量操作 |
| 账号 | 每日提现上限 500 元，单笔上限 200 元 | 与 05-cash-redeem.md 中默认配置一致 |
| 全局 | 平台单日全局提现上限 10 万元，达到后熔断 | 控制单日资金流出峰值 |

### 3.2 提现金额风控

| 金额区间 | 处理方式 |
|:---|:---|
| 0.30 元（首提） | 极速到账，但仅限首次；实名认证 + 设备/IP 校验通过即可 |
| 1~50 元 | 系统自动风控，通过后实时或 T+0 打款 |
| 50~200 元 | 系统复核 + 设备/行为评分校验，评分低于阈值进入人工审核 |
| ≥ 50 元（或单笔 ≥ 100 元） | 强制人工审核，审核通过后再打款，默认 T+1 |

### 3.3 二次验证策略

| 触发条件 | 二次验证方式 | 说明 |
|:---|:---|:---|
| 单日提现超过 1 次 | 短信验证码 | 向绑定手机号发送验证码，60 秒内有效 |
| 单笔提现 ≥ 50 元 | 支付密码 | 用户设置的 6 位数字支付密码，连续 5 次错误锁定 2 小时 |
| 新设备/新 IP/异地登录后提现 | 短信验证码 + 人脸核验 | 高风险场景下强制人脸，确保本人操作 |
| 身份证命中黑灰产名单 | 人脸核验 + 人工复核 | 必须完成活体检测并通过人工审核 |
| 账号行为评分异常 | 短信验证码 + 支付密码 | 多层验证叠加，降低欺诈成功率 |

## 4. 法律与税务合规

### 4.1 用户协议与隐私政策要点

| 文件 | 必须包含的要点 |
|:---|:---|
| 用户协议 | 现金奖励性质说明、汇率与门槛规则、手续费承担方、提现失败处理、平台暂停/拒绝提现权利、反作弊处罚条款、未成年人限制条款、争议解决与管辖法院、规则变更公示方式 |
| 隐私政策 | 实名信息收集目的与范围、身份证/银行卡/支付账号存储与加密方式、信息共享对象（支付机构、实名核验服务商）、用户查询与更正权利、信息保留期限、未成年人信息保护 |

### 4.2 现金奖励的税务处理建议

| 场景 | 处理建议 |
|:---|:---|
| 日常小额提现 | 用户协议中明确告知：用户因参与游戏获得的现金奖励属于个人所得，应依法自行申报个人所得税 |
| 年度/累计提现超过 800 元 | 后台自动标记，并在用户提现页面提示税务申报义务；如当地税务机关要求，平台可按劳务报酬代扣代缴 |
| 代扣代缴模式 | 若采用代扣代缴，需在提现时计算应纳税额，用户到账金额为税后金额；平台按期向税务机关申报并缴纳 |
| 平台侧税务 | 平台需就广告收入、支付手续费等支出取得合规发票，按规定申报增值税、企业所得税等 |

### 4.3 反洗钱（AML）基本义务

| AML 义务 | 具体措施 |
|:---|:---|
| 客户身份识别 | 首次提现前完成实名认证；大额/高频提现增加人脸或人工复核 |
| 可疑交易监测 | 监控同一设备/IP/身份证多账号、高频提现、整数倍大额提现、夜间批量操作等异常模式 |
| 交易记录保存 | 用户身份信息、交易流水、对账记录保存不少于 5 年 |
| 大额交易报告 | 单笔或当日累计提现超过 5 万元时，按监管要求上报 |
| 内部制度与培训 | 建立 AML 内控制度，定期对运营、客服、风控人员进行培训 |

## 5. 风控评分模型建议

### 5.1 风险评分卡

| 评分维度 | 权重 | 低风险（加分/低分） | 中风险 | 高风险（高分） |
|:---|:---:|:---|:---|:---|
| 设备指纹 | 25% | 常用设备、设备信息完整、无异常 | 新设备、部分信息缺失 | 模拟器/云手机/多开、设备指纹命中黑名单 |
| 账号年龄 | 15% | 注册 ≥ 30 天，活跃正常 | 注册 7~30 天 | 注册 < 7 天或长期沉睡后突然活跃 |
| 历史行为 | 20% | 游戏行为正常、通关路径合理、无处罚记录 | 偶发轻微异常 | 多次作弊、被处罚、金币增速异常 |
| 提现频率 | 20% | 提现间隔合理、金额与历史一致 | 近期提现次数增加 | 高频提现、多账号同一身份证提现 |
| 实名一致性 | 15% | 实名与支付账户一致、已完成人脸 | 实名信息存在轻微不一致 | 实名与支付账户不一致、疑似冒用 |
| 其他（IP/地理位置） | 5% | 常用 IP、地理位置稳定 | IP 变动但可解释 | VPN/代理、异地登录、境外 IP |

**评分规则：**

- 总分 0~100 分，按各维度加权求和。
- 0~30 分：低风险，自动通过，实时打款。
- 31~60 分：中风险，增加短信/支付密码验证，部分进入系统复核。
- 61~80 分：高风险，强制人工审核，延迟打款。
- 81~100 分：极高风险，拒绝提现并冻结账号，进入黑灰产调查。

### 5.2 评分模型应用流程

```text
用户提交提现申请
    │
    ▼
实名认证与一致性校验
    │
    ▼
多维度风控评分（设备/账号/行为/频率/实名/IP）
    │
    ▼
根据评分结果分流处理
    │
    ├── 低风险 ──▶ 自动通过，进入支付通道打款
    │
    ├── 中风险 ──▶ 触发二次验证，验证通过后打款
    │
    ├── 高风险 ──▶ 进入人工/系统复核，T+1 处理
    │
    └── 极高风险 ──▶ 拒绝提现，冻结账号，人工调查
```

## 6. 上线前必须完成的合规 Checklist

### 6.1 实名认证

- [ ] 完成微信实名授权接入，获取并核验用户实名信息。
- [ ] 完成支付宝实名授权接入或作为备选方案。
- [ ] 接入第三方身份证 OCR + 二要素核验服务商，并签署数据安全协议。
- [ ] 实现首次提现前强制实名认证逻辑。
- [ ] 实现实名信息绑定后不可自行修改，需人工审核变更。
- [ ] 实现身份证年龄判定，未成年人账号禁止提现并接入防沉迷系统。
- [ ] 实名信息与支付账户实名一致性校验上线。

### 6.2 反作弊

- [ ] 客户端代码混淆、内存加密、签名校验、模拟点击检测方案落地。
- [ ] 服务端单局结算用时、收集数量、通关路径、星级一致性校验上线。
- [ ] 金币增长速率监控与异常账号标记机制上线。
- [ ] 作弊处置策略（警告/冻结/清零/封号）配置到运营后台。
- [ ] 建立作弊申诉与复核流程。

### 6.3 提现风控

- [ ] 设备/IP/身份证维度限频规则配置并生效。
- [ ] 单笔/单日/单月提现上限配置并生效。
- [ ] 大额提现人工审核流程（≥ 50 元或单笔 ≥ 100 元）上线。
- [ ] 二次验证（短信验证码、支付密码、人脸核验）接入完成。
- [ ] 全局提现熔断与对账差异处理机制上线。

### 6.4 法律与税务

- [ ] 用户协议与隐私政策更新，覆盖现金奖励、实名信息、提现规则、未成年人保护、反作弊处罚等条款。
- [ ] 用户协议与隐私政策在首次启动、提现页面、设置页显著位置展示并获取同意。
- [ ] 税务处理方案确定（代扣代缴或用户自行申报），并在用户协议与提现页面披露。
- [ ] 反洗钱内控制度建立，可疑交易监测规则与报告流程上线。
- [ ] 用户身份信息、交易流水、对账记录保存期限配置为不少于 5 年。

### 6.5 支付与数据安全

- [ ] 仅使用持牌支付机构或银行官方接口，完成商户号/支付宝企业账号开通与签约。
- [ ] API 证书、密钥妥善保存于服务端，实行最小权限访问与定期轮换。
- [ ] 身份证、银行卡、openid 等敏感信息加密存储，传输使用 TLS 1.2 以上。
- [ ] 完成支付通道对账与差异处理流程测试。
- [ ] 风控评分模型上线，并按评分结果自动分流处理。

### 6.6 运营与审计

- [ ] 运营后台配置汇率、门槛、手续费、时间窗口等风控参数，并记录操作日志。
- [ ] 用户金币流水、现金流水、对账表结构落地，所有资金变动可追溯。
- [ ] 客服处理提现申诉、作弊申诉、实名变更的标准话术与工单流程准备完成。
- [ ] 上线前完成风控策略灰度测试与压力测试。
