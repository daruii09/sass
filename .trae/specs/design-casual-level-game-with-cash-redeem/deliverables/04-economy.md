# Task 4：金币经济系统设计

## 1. 金币获取途径与数值公式

### 1.1 基础奖励公式

| 项目 | 公式 | 说明 |
|:---|:---|:---|
| 通关基础奖励 | `关卡基础值 × 星级系数` | 失败时无基础奖励，仅保留已收集金币 |
| 一星系数 | 1.0 | 通关即点亮时间星/收集星/无伤星中的任意一颗 |
| 二星系数 | 1.2 | 点亮两颗星 |
| 三星系数 | 1.5 | 三颗星全部点亮 |

关卡基础值引用 `02-level-design.md` 中的关卡基础金币奖励表；星级评定标准（时间 / 收集 / 无伤）亦沿用该文档。

### 1.2 关卡内收集奖励

| 收集物 | 单份价值 | 说明 |
|:---|:---:|:---|
| 普通金币 | 1 枚 | 关卡内最常见的可收集物 |
| 大宝箱 | 50 枚 | 固定位置或击败 Boss 后掉落 |
| 隐藏星星 | 100 枚 | 隐藏路径或秘密区域中的高价值收集物 |

### 1.3 结算加成

加成按“通关基础奖励 + 关卡内收集奖励”的合计值为基数计算，多个加成之间为加法叠加。

| 加成类型 | 加成比例 | 触发条件 |
|:---|:---:|:---|
| 无伤加成 | +10% | 本局获得“无伤星” |
| 速通加成 | +10% | 通关用时 ≤ 该关时间星标准 |
| 连击收集加成 | +5% / 档，上限 50% | 每连续收集 10 枚普通金币 +5%，拾取宝箱/隐藏星星或漏捡时重置连击 |

### 1.4 总金币结算公式

```text
基础奖励   = 关卡基础值 × 星级系数
收集奖励   = 普通金币数 × 1 + 大宝箱数 × 50 + 隐藏星星数 × 100
加成系数   = 1 + 无伤加成 + 速通加成 + 连击加成
本局金币   = floor( (基础奖励 + 收集奖励) × 加成系数 )
```

所有结算取整数，`floor` 表示向下取整。

### 1.5 示例：第 5 关三星通关收益

以 W1-5「滚石坡道」为例：

- 关卡基础值：90
- 星级：三星，星级系数 1.5
- 局内收集：普通金币 30 枚 + 大宝箱 1 个
- 达成：无伤通关
- 未触发：速通、连击加成

计算过程：

```text
基础奖励 = 90 × 1.5 = 135
收集奖励 = 30 × 1 + 1 × 50 = 80
小计     = 135 + 80 = 215
无伤加成 = 215 × 10% = 21.5 → 取整 21
最终获得 = 215 + 21 = 236 枚金币
```

**结果：玩家最终获得 236 枚金币。**

## 2. 每日任务表

每日任务每日 00:00（北京时间）刷新，刷新后进度与领取状态重置；未领取的奖励通过邮件补发，邮件有效期 7 天。

| 任务名称 | 任务内容 | 完成条件 | 金币奖励 | 刷新规则 |

| 闯关先锋 | 完成日常闯关 | 今日通关任意关卡 3 次 | 150 | 每日 00:00 重置进度与领取状态 |
| 金币收藏家 | 单局大量收集 | 单局累计收集普通金币 ≥ 200 枚 | 200 | 每日 00:00 重置进度与领取状态 |

| 无伤达人 | 保持无伤通关 | 今日完成无伤通关 ≥ 2 次 | 300 | 每日 00:00 重置进度与领取状态 |
| 广告支持者 | 观看激励视频 | 今日观看激励视频 ≥ 3 次（复活/翻倍/挑战次数） | 400 | 每日 00:00 重置进度与领取状态 |
| 挑战参与者 | 参与每日挑战 | 完成 1 次每日挑战模式 | 300 | 每日 00:00 重置进度与领取状态 |

| 第 4 天 | 250 | 无 |

## 5. 金币服务端存储与防篡改方案

### 5.1 服务端权威存储

- 金币余额以服务端数据库记录为唯一权威值，客户端仅负责展示服务端下发的余额。
- 任何金币变动（结算、任务、签到、成就、运营补偿、处罚扣减）必须通过服务端事务写入，禁止客户端直接修改本地余额后同步。
- 推荐账户表字段：

| 字段 | 类型 | 说明 |
|:---|:---|:---|
| `user_id` | bigint / string | 用户唯一标识 |
| `gold_balance` | int | 当前金币余额，服务端权威值 |
| `frozen_gold` | int | 冻结中金币（如提现审核中） |
| `total_earned` | int | 累计获得金币，用于审计与风控 |
| `version` | int | 乐观锁版本号，防止并发覆盖 |
| `updated_at` | timestamp | 最后更新时间 |

### 5.2 单局结算上报与校验流程

1. 开局时客户端向服务端申请关卡会话 `session_id`，服务端记录关卡配置版本、会话创建时间、关卡 ID。
2. 单局结束后，客户端上传结算报文。
3. 服务端根据关卡配置和规则独立计算应得金币，与客户端上报值比对，超出阈值或无法复现则标记异常。
4. 校验通过后，使用 `session_id` 进行幂等扣减/发放，避免重复奖励。

客户端上报字段示例：

| 字段 | 说明 |
|:---|:---|
| `session_id` | 开局时服务端分配的唯一会话 ID |
| `level_id` | 关卡编号，如 W1-5 |
| `stars` | 最终星级 1~3 |
| `normal_coin_count` | 普通金币收集数量 |
| `chest_count` | 大宝箱收集数量 |
| `hidden_star_count` | 隐藏星星收集数量 |
| `duration_ms` | 通关用时，毫秒 |
| `no_damage` | 是否无伤 |
| `combo_max` | 本局最高普通金币连击数 |
| `client_ts` | 客户端结算时间戳 |
| `signature` | 客户端对关键字段的签名，服务端验签 |

### 5.3 关键校验规则

| 校验项 | 规则 | 异常处理 |
|:---|:---|:---|
| 用时合法性 | `duration_ms` 必须大于该关理论最短时间，且不超过关卡最大时长 | 标记异常，仅发放已收集金币或拒绝结算 |
| 收集数量上限 | 各类收集物数量不得超过该关卡配置中对应实体的总数 | 超出部分不计入奖励，并标记异常 |
| 通关可达性 | 校验通关路径是否物理可达；关键操作需提供操作轨迹或状态哈希供服务端抽样复核 | 无法复现则冻结奖励并进入人工复核 |
| 时间戳校验 | 结算时间必须在会话创建时间之后，且与服务端时间差 ≤ 5 分钟；拒绝过期或倒序时间戳 | 拒绝结算并记录日志 |
| 星级一致性 | 根据 `duration_ms`、收集数量、`no_damage` 反推星级，与客户端上报星级比对 | 星级不一致时按服务端计算结果发放 |
| 幂等性 | 同一 `session_id` 只能结算一次 | 重复上报直接返回已结算结果 |
| 签名校验 | 校验客户端签名，确认报文未被篡改 | 验签失败拒绝结算 |

## 6. 金币经济平衡估算

### 6.1 核心假设

| 项目 | 假设值 | 说明 |
|:---|:---:|:---|
| 汇率 | 10000 金币 = 1 元 | 固定汇率，运营可调整 |
| 日均活跃玩家闯关数 | 8 关/日 | 以中后期玩家平均水平估算 |
| 平均关卡基础值 | 150 | 综合 W1~W3 关卡进度的均值 |
| 平均星级系数 | 1.3 | 玩家熟练后平均约 2.3 星 |
| 平均每局收集普通金币 | 45 枚 | 含宝箱/隐藏星星折算后约等值 |
| 平均结算加成 | 15% | 主要来源为无伤和少量连击 |
| 每日任务完成率 | 100% | 以全部完成为基准估算上限 |
| 成就均摊 | 200 金币/日 | 一次性成就按 60 天均摊 |

### 6.2 日均金币产出估算

| 来源 | 计算方式 | 日均产出 |
|:---|:---|---:|
| 关卡结算 | `floor((150×1.3 + 45) × 1.15) × 8 = 276 × 8` | 2208 |
| 每日任务 | 7 个任务全部完成 | 1700 |
| 签到奖励 | 周均 3050 ÷ 7 | 436 |
| 成就均摊 | 12700 ÷ 60 天 | 212 |
| **合计** | | **4556 枚金币/日** |

按固定汇率折算，**活跃玩家日均金币产出约 0.46 元现金价值**。

### 6.3 广告收入对补贴的覆盖能力

| 项目 | 假设值 | 计算 |
|:---|:---|---:|
| 日均广告展示次数 | 15 次/人 | 含激励视频、插屏、Banner |
| 混合 eCPM | 20 元/千次 | 激励视频偏高，Banner 偏低 |
| 日均广告收入 | 15 × 20 ÷ 1000 | **0.30 元/人/日** |
| 补贴覆盖比例 | 0.30 ÷ 0.46 | **约 65%** |

广告收入可覆盖约 65% 的金币现金成本，剩余 35% 通过以下方式平衡：

- 平台流量补贴与广告主激励预算；
- 控制实际兑换率与提现门槛；
- 非现金道具/复活/挑战次数等回收金币；
- 后期引入轻度内购（如去广告、皮肤）。

### 6.4 兑换现金的成本模型

| 指标 | 数值 | 说明 |
|:---|---:|:---|
| 汇率 | 10000 金币 = 1 元 | 固定汇率 |
| 最低提现门槛 | 10 元 | 即 100000 金币 |
| 达到门槛所需天数 | 约 22 天 | 按日均 4556 金币计算 |
| 理论现金负债/DAU/日 | 0.46 元 | 不考虑回收与兑换率 |
| 实际兑换率假设 | 40% | 受门槛、留存、风控影响 |
| 实际现金流出/DAU/日 | 0.18 元 | 0.46 × 40% |
| 广告收入/DAU/日 | 0.30 元 | 见 6.3 |
| 单 DAU 日毛利估算 | 0.12 元 | 0.30 - 0.18 |

## 7. 防作弊关键点

- **服务端权威**：金币余额、所有增减流水必须以服务端数据库为准，客户端只读，禁止本地修改后同步。
- **全链路校验**：结算用时时长、收集数量、星级、通关路径等关键字段必须与服务端关卡配置交叉验证。
- **报文防篡改**：关键结算字段使用服务端密钥签名校验，防止抓包修改。
- **时间窗口控制**：会话创建、结算上报、时间戳必须满足单调递增与合理时间窗口，杜绝旧数据重放。
- **上限阈值监控**：每关预设理论最大金币、理论最短用时、最大收集数，超出即进入风控队列。
- **行为模式识别**：监控同一设备/IP/账号短时间内高频提现、异常金币增速、脚本特征，触发冻结与人工复核。
- **幂等与审计**：所有金币变动使用唯一事务 ID 保证幂等，留存完整流水日志，支持事后追溯与对账。
