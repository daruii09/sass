# Task 1：确定游戏核心玩法与技术方案

## 1. 游戏类型：竖版平台跳跃闯关

推荐采用**竖版平台跳跃闯关（Vertical Auto-Runner Platformer）**，具体形式为：角色自动向前奔跑，玩家通过单指点击/上下滑动控制跳跃、二段跳与滑铲，目标为在限定时间内到达终点或收集足够金币。

- **单手操作友好**：竖版布局天然适配手机握持，拇指即可完成全部操作，通勤、站立等碎片化场景可快速开局。
- **自动前进降低门槛**：无需左右移动控制，玩家只需判断“跳”或“滑”，减少 3D 自由移动带来的认知负担，符合休闲用户画像。
- **关卡长度可控**：每局时长 30~90 秒，适合广告点插入（如失败后看广告复活、结算后激励视频翻倍），也符合“赚金币”的高频反馈节奏。
- **竖版屏幕利用率更高**：障碍物、金币、平台可沿垂直方向分层排布，前景背景纵深明显，视觉冲击强且关卡编辑简单。
- **与小游戏生态契合**：微信小程序、抖音小游戏等平台对竖版轻度游戏流量扶持较大，分享截图/录屏传播效果更佳。

## 2. 技术引擎与平台选择

### 2.1 候选方案对比

| 维度 | Unity | Cocos Creator 3.x + TypeScript | 微信小游戏原生方案 |
|------|-------|--------------------------------|--------------------|
| 包体大小 | 较大（空包 10MB+），对微信小游戏不友好 | 较小（可精简至 5MB 以内） | 极小（纯 JS） |
| 跨平台能力 | iOS/Android/PC/主机/小游戏均可，但小游戏需适配 | 一次开发，可发布 iOS/Android/微信/抖音/网页 | 仅限微信生态 |
| 开发效率 | 组件成熟、社区大，但脚本为 C#，编译链路较长 | TypeScript 工程化成熟，脚本即源码，热更新灵活 | 需自行搭建框架，长期维护成本高 |
| 美术管线 | 2D/3D 资源管线完善 | 2D 与轻度 3D 支持良好，3D 重度效果弱于 Unity | 依赖开发者自行整合 |
| 团队成本 | 需 Unity 客户端经验 | 前端/小游戏团队可快速上手 | 需从零沉淀工具链 |

### 2.2 推荐方案：Cocos Creator 3.x + TypeScript

- **兼顾 APP 与微信小游戏**：同一工程可同时构建 Android/iOS 原生包与微信/抖音小游戏包，避免两套代码维护。
- **TypeScript 工程化成熟**：强类型、VS Code 生态完善、模块化管理方便，便于多人协作与长期迭代。
- **包体与性能平衡**：引擎本身轻量，适合休闲 2D 平台跳跃，小游戏加载速度快，留存率更高。
- **原生扩展与热更新**：支持 iOS/Android 原生插件与脚本热更新，后续可灵活接入广告 SDK、支付 SDK。

### 2.3 发布路径

1. **MVP 阶段**：优先发布微信小程序版本，快速验证核心玩法与金币兑换闭环。
2. **扩量阶段**：基于同一工程构建 Android APK/iOS IPA，上架应用商店，接入穿山甲/AdMob 等广告变现。
3. **长线阶段**：视数据表现接入抖音小游戏、OPPO/vivo 快游戏等渠道，形成多平台矩阵。

## 3. 操作方式与单局规则

### 3.1 输入方式

- **点击屏幕任意位置**：角色执行普通跳跃。
- **快速双击/连续点击两次**：触发二段跳（空中再跳一次）。
- **向下滑动**：角色进入滑铲/下蹲状态，持续 0.5 秒，可穿过低矮障碍或击倒特定敌人。
- **向上滑动（可选）**：与点击等价，用于满足部分玩家“上滑跳跃”的肌肉记忆。
- **点击暂停按钮**：弹出暂停菜单，可继续、重试或返回关卡列表。

### 3.2 角色动作

- **奔跑**：角色自动沿关卡路径匀速前进，速度随关卡难度略微提升。
- **跳跃**：离地后受重力影响呈抛物线轨迹，可通过点击时机控制跳跃高度与落点。
- **二段跳**：在空中再次点击可二次腾空，用于跨越较长深渊或躲避连续障碍。
- **滑铲/下蹲**：向下滑动后角色贴地滑行，期间可躲避高悬障碍、穿过狭窄通道，并对低矮小怪造成踩踏击退。
- **受击/死亡**：触碰尖刺、坠落深渊、撞击敌人或被 Boss 技能命中时扣除生命值，生命值为 0 或超时即失败。

### 3.3 胜利与失败条件

- **胜利条件**：角色抵达关卡终点旗帜处，或完成该关特定目标（如收集指定数量金币、击败关卡 Boss）。
- **星级评价**：根据通关时间、收集金币数、剩余生命值综合评定 1~3 星。
- **失败条件**：生命值归零、跌落场景外、超时未完成通关目标。
- **复活机制**：失败后提供“观看激励视频复活”选项，复活后角色回到最近检查点，每局限 1 次。

## 4. 核心循环

完整玩家旅程如下：

1. **打开游戏**：启动页加载资源并展示品牌 Logo，进入主界面时自动登录/游客账号初始化。
2. **进入主界面**：展示当前金币余额、现金余额、每日任务入口、签到入口、关卡选择入口、设置入口。
3. **选择关卡**：进入关卡选择页，玩家可滑动查看已解锁世界与关卡，每关显示最高星级与锁定状态。
4. **开始闯关**：点击关卡后进入 Loading 界面，加载完成后进入单局，HUD 显示金币、生命、时间、进度。
5. **局内挑战**：玩家通过跳跃、二段跳、滑铲躲避障碍与敌人，收集金币、宝箱与道具。
6. **关卡结算**：胜利或失败后进入结算页，展示用时、收集金币、星级评价、任务进度、可领取奖励。
7. **领取金币**：基础通关奖励 + 星级加成 + 局内收集金币自动进入账户；每日任务/签到奖励可手动领取。
8. **兑换现金**：在兑换页输入金币数量，按当前汇率换算为现金，确认后扣除金币并生成待提现订单。
9. **发起提现**：在提现页选择到账方式（微信/支付宝/银行卡），满足最低门槛与实名认证后提交申请。
10. **等待到账**：提现订单进入审核/打款流程，玩家可在记录页查看状态与预计到账时间。

## 5. 关键界面定义

### 5.1 启动页

- 显示游戏 Logo、版本号、健康游戏忠告。
- 后台静默完成资源校验、版本更新检查、游客登录/账号登录。
- 加载完成后淡入主界面，首次启动可插入简短新手引导入口。

### 5.2 主界面

- 顶部信息栏：金币余额、现金余额、设置、公告。
- 中部核心入口：开始闯关、关卡选择、每日挑战。
- 底部功能栏：每日任务、签到、兑换/提现、背包、我的。
- 视觉重点突出“开始闯关”与“金币/现金余额”，强化核心循环感知。

### 5.3 关卡选择页

- 世界切换：横向滑动切换 3 大世界，每个世界包含 10 个小关。
- 关卡节点：已通关显示最高星级，当前可玩关卡高亮，未解锁关卡显示锁图标与解锁条件。
- 每日挑战入口：独立入口展示今日主题、剩余时间、额外奖励预览。
- 返回按钮：返回主界面。

### 5.4 游戏内 HUD

- 左上角：暂停按钮、当前生命值（爱心图标）。
- 顶部中央：关卡进度条，显示角色距终点距离。
- 右上角：本局已收集金币数、剩余时间。
- 左下角（可选）：道具快捷栏（护盾、磁铁、双倍金币）。
- 底部不可见区域为操作区，全屏响应点击与滑动。

### 5.5 结算页

- 胜利态：展示星级评价、通关用时、本局获得金币明细、任务进度更新、按钮组“下一关”“重玩”“返回关卡列表”“观看广告翻倍”。
- 失败态：展示失败原因、本局已获得金币、按钮组“重试”“观看广告复活”“返回关卡列表”。

### 5.6 兑换页

- 展示当前金币余额、现金余额、当前汇率、最低兑换门槛。
- 输入框支持快速选择“全部兑换”“1000 金币”“5000 金币”等快捷档位。
- 确认兑换前展示风险提示：兑换后不可撤销、汇率可能调整。
- 确认后生成待提现订单，跳转提现页或返回我的余额页。

### 5.7 提现页

- 展示可提现现金余额、到账方式列表（微信/支付宝/银行卡）、实名认证状态。
- 未实名用户提示先完成实名认证，并跳转实名认证流程。
- 输入提现金额，校验是否满足最低门槛与当日/单笔限额。
- 提交后展示订单状态：审核中、打款中、已到账、被驳回，并提供客服入口。

## 6. 关键技术风险与建议

- **小游戏包体与加载性能**：Cocos Creator 构建微信小游戏时，若资源过大可能导致首次加载时间过长。建议采用资源分包、压缩纹理、延迟加载关卡资源，并将首包控制在 4MB 以内。
- **跨平台输入一致性**：不同机型屏幕比例、触控采样率差异可能导致“滑动识别为点击”或“误触”。建议在早期进行多机型触控测试，并设置合理的滑动阈值与防误触缓冲。
- **金币经济安全**：客户端与服务端金币数据必须分离，客户端仅展示，所有金币变动由服务端校验后下发。关键操作（结算、兑换、提现）需服务端验签，防止抓包篡改。
- **广告与支付合规**：微信小游戏对激励视频、提现类玩法有明确审核规范，需在项目初期阅读最新平台政策，避免“诱导分享”“虚假宣传到账”等违规描述。
- **汇率与提现状态一致性**：运营调整汇率或门槛后，已生成订单不应受影响。建议在数据库中记录订单生成时的汇率快照，并在结算/提现状态机中加入幂等控制，防止重复发放或扣款。
